The Problem: All-or-Nothing Agent Access

Modern AI agents (Claude Code, Cursor CLI, OpenAI Operator) communicate with tools over the Model Context Protocol (MCP). Standard email connectors provide unconditional read access to every message. If an agent executes a routine inbox search, raw verification OTPs, medical lab results, and corporate salaries are sent unmasked to cloud LLM providers, while invisible HTML prompt injections can silently hijack the agent's instructions.

How Spindle Works: The 4-Layer Security Pipeline

Spindle functions as an intelligent reverse proxy. Every tool call from the agent passes through four sequential gates before any data reaches the model context:

1. Policy Precedence

Deterministic checks enforce category actions (allow, ask, deny) defined in user-controlled YAML policies.

2. Dual-Stage Classifier

Deterministic keyword rules + local SLM classify messages into 8 categories (Work, Personal, Finance, Health, Auth, etc.).

3. Injection Guard

HTML parser detects hidden text, 0px fonts, and CSS concealment; 6 regex heuristics identify override attempts.

4. 16-Stage Redaction

Masks OTPs, SSNs, credit cards (Luhn-checked), bank accounts, medication names, and salaries before delivery.

Microsoft Track Criteria Alignment

How Spindle demonstrates prototype-to-production excellence and responsible AI engineering.

🎯 1. Customer Understanding

Users adopting autonomous desktop agents (Claude Code, Cursor CLI, Copilot) frequently hit an unsettling barrier: personal and work contexts collide. As highlighted by privacy leaders and industry research, once private data enters agent context windows, it moves across third-party LLM pipelines with zero governance. Spindle is built for the thousands of developers and professionals who want agent assistance without forfeiting inbox confidentiality.

📊 2. Measurable Usefulness

Spindle's impact is quantifiable: in an inbox of 17 emails, Spindle reduces exposed sensitive tokens from 38 down to 0, shields 100% of medical and auth secrets, and drops unauthorized personal exposure by 58.8% (holding 3 personal/financial emails in human approval queue). In rigorous automated testing, permission rules stopped 100% of directory and policy bypass attempts (3/3 blocked, 0/17 injection exfiltration across Grok model tiers).

☁️ 3. Path to Production (Azure)

Spindle separates the Control Plane (hosted on Azure App Service with Microsoft Entra ID authentication and Azure Key Vault for per-agent secrets) from the Data Plane (local stdio or Streamable-HTTP MCP). Policies are signed by the user, and remote agents authenticate via per-agent Bearer tokens.

🛡️ 4. Responsible Design

Spindle adheres to fail-closed, defense-in-depth principles: deterministic regex filters take absolute precedence over probabilistic LLM decisions; an immutable SQLite audit trail preserves the exact text seen by every agent; and all sensitive PII is stripped before any text touches language models.

🚀 5. End-to-End Functionality

Spindle is fully operational today: a complete local gateway running over stdio MCP in Cursor CLI and Claude Code, alongside a hosted cloud deployment on Azure App Service featuring Microsoft Entra ID single sign-on, a real-time policy dashboard, and live human-in-the-loop approval workflows.
